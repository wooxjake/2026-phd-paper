# 논문 번역 가이드라인

## 목적

이 폴더의 번역 파일은 원문을 요약한 것이 아니라, 원문 구조와 내용을 가능한 한 충실하게 한국어로 옮긴 문서로 작성한다.

## 상태 체계

- 자동 번역이 끝난 파일은 완료본이 아니라 `generated` 상태이다. 이 상태는 PDF 텍스트 추출, 구조 파싱, 기계번역, Markdown 생성만 끝났음을 뜻한다.
- `generated` 파일은 기본적으로 `review-required` 상태로 취급한다. 자동 생성 직후에는 문맥, 번역의 자연스러움, 의미 보존 여부가 검토되지 않았으므로 논문 본문에 반영하거나 완료로 표시하지 않는다.
- `reviewed` 상태는 AI 또는 사람이 원문과 번역문을 대조하여 문단 흐름, 인과관계, 수치·단위·통계 표현, 인용, 표·그림 주변 문맥, OCR 잔여 문구를 검토한 경우에만 부여한다.
- `ready` 상태는 `reviewed` 검토에서 문제를 수정하고 품질 기준을 모두 충족하여 논문 반영이 가능한 경우에만 부여한다.
- 자동 생성 스크립트의 성공 출력은 파일 생성 성공만 의미하며, 번역 검토 완료나 `ready` 상태를 의미하지 않는다.
- 상태는 번역 Markdown 파일 상단의 논문 정보 아래에 다음 중 하나로 기록한다: `<!-- Translation status: generated -->`, `<!-- Translation status: review-required -->`, `<!-- Translation status: reviewed -->`, `<!-- Translation status: ready -->`.

## 자동 번역 후 검토

- 모든 자동 생성 번역본은 AI 또는 사람의 원문 대조 검토를 거쳐야 한다.
- 검토에서는 문단의 논리 흐름, 원문의 비교·인과관계, 수치·단위·p값·신뢰구간, 본문 인용, 표·그림·References의 위치와 문맥, OCR 잔여 문구를 확인한다.
- 한국어 문장이 부자연스럽거나 문맥이 끊긴 경우에는 문장만 교정하지 말고 원문 문단을 다시 대조하여 의미와 논리 순서를 복구한다.
- `/C0`, 깨진 문자, 문장 중간 잘림, 비정상적 한영 혼용, 반복 머리말·쪽수·저널명, 표·그림 이후 단절된 설명이 확인되면 해당 파일은 `review-required` 상태로 유지한다.
- `reviewed` 또는 `ready` 상태는 자동 검사 통과만으로 부여하지 않는다.

## 번역 코드 변경 중단 규칙

- 번역 품질, 구조 보존 또는 상태 표기를 개선하기 위해 `batch_translate_papers.py`, `extract_pdf_text.py`, 의존성, 또는 자동화 테스트의 수정이 필요하다고 판단되면 즉시 작업을 중단한다.
- 중단 시에는 코드 수정이 필요한 이유, 예상되는 영향 범위, 기존 번역 파일 재생성 또는 재검토 필요 여부를 사용자에게 보고하고 승인을 기다린다.
- 사용자 승인 전에는 번역 코드를 수정하거나 기존 번역 파일을 자동 재생성하지 않는다. 코드 외의 수동 번역문 검토·정리와 가이드라인 보완만 수행할 수 있다.

## 기본 원칙

- 원문 제목은 영어 제목을 유지하되, 한국어 제목을 함께 표기한다.
- 논문의 섹션 구조(예: Abstract, Introduction, Methods, Results, Discussion, Conclusions, References)를 유지한다.
- 문단 단위로 번역하고, 필요하면 문장 분해를 통해 읽기 쉬운 한국어로 재구성하되 요약이나 생략은 피한다.
- 페이지마다 반복되는 머리말, 쪽수, 저널명 표시는 번역하지 말고 제거한다. 예: `Sensors 2025, 25, 5963 3 of 20`
- 페이지 경계는 반복 머리말과 분리하여 `<!-- Page 3 -->` 형식으로 표시한다.
- 기술 용어와 약어는 원문과 함께 유지한다. 예: sEMG, MIMU, ROM, LBP.
- 본문 인용과 References의 인용 스타일은 원문 형식을 그대로 유지한다. 원문이 번호형 인용이면 번호, 순서, 본문-References 대응 관계를 유지한다. 예: [8]
- 원문이 저자-연도 인용이면 저자명, 연도, 구두점 및 References의 배열 방식을 유지한다. 예: (Harrison et al., 1999).
- 번역 중에는 인용을 번호형, 저자-연도형 또는 문장 내 설명형으로 임의 변환하지 않는다.
- 저자-연도 인용 논문을 번호형 인용으로 바꿔야 하는 경우, 번역본 자체를 고치지 말고 논문 반영용 별도 버전에서만 변환한다.
- DOI, URL, 저자명, 저널명, 수치, p값, 표/그림 설명은 가능한 한 원문 그대로 유지한다.
- 번역 중에는 불필요한 해석 주석이나 개인 의견을 추가하지 않는다.

## 예외 사항

- 번역이 필요 없는 문서는 번역하지 않는다. 예를 들어, 이미 한국어로 작성된 메모, 정책 문서, 가이드라인, 분석 노트, README, 체크리스트, 초안 메모, 논문 작성 메모 등은 원문 그대로 유지한다.
- 원문이 이미 한국어이거나, 번역 대상이 아닌 문서(예: 실험 절차 메모, 연구 계획서, 개인 메모, 작업 지시서)도 번역하지 않는다.
- 파일명이 'x\_'로 시작하는 문서는 번역 대상에서 제외한다.
- 원문 PDF가 없거나 텍스트를 확보할 수 없는 경우에는 새 번역 파일을 만들지 않고, 해당 파일을 건너뛰며 간단한 메모만 남긴다.
- 이미 번역본이 존재하는 경우에는 중복으로 다시 번역하지 않는다.
- 표/차트, 이미지, 스크린샷만 있는 자료는 본문 번역 대상이 아니며, 필요하면 짧은 설명만 추가한다.

## 실행 환경

- PDF 텍스트 추출에는 [references/extract_pdf_text.py](references/extract_pdf_text.py) 를 사용한다.
- PDF 표 추출에는 `pdfplumber`를 사용한다.
- 새 가상환경을 만들지 않고, 기존 프로젝트 가상환경인 [.venv](.venv) 를 사용한다.
- Windows PowerShell 기준으로 활성화는 다음과 같이 수행한다.
  - .\.venv\Scripts\Activate.ps1
- 실행이 필요할 때는 다음처럼 사용한다.
  - .\.venv\Scripts\python.exe references\extract_pdf_text.py
- 가능하면 같은 환경에서 번역 작업과 추출 작업을 모두 처리한다.

## 작성 스타일

- 학술 문서에 적합한 공손하고 정제된 한국어를 사용한다.
- 문장은 문맥을 고려하여 자연스럽게 이어지도록 다듬되, 원문의 의미와 논리 전개가 흐려지지 않도록 한다.
- 문체는 이다체로 통일한다.
- 문장 길이가 지나치게 길어지지 않도록 하되, 원문의 의미가 흐려지지 않도록 한다.
- 표/그림이 있는 경우 번역본에도 해당 구조와 번호를 유지한다. Markdown 표 변환은 열, 행, 병합 셀, 각주 및 수치 정보가 손실되지 않는 경우에만 적용한다.
- 자동 변환은 표의 캡션, 열 제목, 모든 데이터 행 및 각주를 추출하고 각 데이터 행의 열 수를 확인할 수 있는 경우에만 Markdown 표를 생성한다.
- 병합 셀, 다단 헤더, 셀 내 줄바꿈, 이미지 기반 표, 열 수 불일치 또는 추출 오류가 있으면 Markdown 표로 변환하지 않는다. 이 경우 캡션과 원문 위치를 유지하고 `<!-- REVIEW REQUIRED: Table n -->` 및 `- 원본 표: PDF 참조`를 남긴다.
- 표를 일반 문단으로 합쳐 출력하는 것은 금지한다.
- 표, 그림, 각주 등 삽입 요소가 본문 중간에 들어가면 위아래 한 줄씩 띄워 배치한다.
- 그림과 표의 캡션은 번역하여 원문의 위치에 유지한다. 원본 이미지나 도표를 삽입할 수 없으면 캡션 아래에 `- 원본 이미지/도표: PDF 참조`라고 표시하며, 캡션·번호·본문의 참조 문구는 삭제하지 않는다.
- 페이지 경계만 `<!-- Page n -->`으로 유지하고, 반복 머리말, 저널명, 쪽수, 다운로드 문구는 제거한다.
- 섹션 제목과 하위 소제목은 문단과 분리해 줄바꿈으로 명확히 구분한다. 예: `2. Materials and Methods`, `2.1. Study Design and Setting`
- References는 한 문단에 몰아쓰지 말고, 항목별로 줄바꿈하여 정렬한다.
- 제목, 소제목, 목록, 표, 각주 등 기본적인 문서 정렬을 유지해 읽기 쉽게 구성한다.
- 문장 끝에 `[CITE?]`가 필요하면 논문 작성 단계에서 참고문헌 확인을 진행한다.

## References 규칙

- References 섹션의 제목과 내용은 번역하지 않고 영어 원문 그대로 유지한다.
- References는 원문의 영어 서지 형식, 인용 스타일, 번호 유무, 순서 및 항목 구성을 그대로 보존한다. 번역 과정에서 APA 형식으로 강제 변환하지 않는다.
- 번호형 인용 논문은 본문 인용 번호와 References 번호가 일대일로 대응되는지 확인하며, 번호를 누락하거나 재배열하지 않는다.
- 저자-연도 인용 논문은 본문의 저자명·연도 표기와 References 항목을 대조해 누락 여부를 확인하며, 원문의 배열 방식을 임의로 변경하지 않는다.

## 논문 반영용 변환 규칙

- 번역본을 draft.md 등 논문 작성용 문서에 반영할 때는, 필요에 따라 저자-연도 인용을 번호형 인용으로 별도 변환할 수 있다.
- 이 변환은 번역본 파일에서 직접 수행하지 않고, 논문 반영용 별도 문서 또는 별도 단계에서만 수행한다.
- 번호형 인용으로 변환할 때는 본문 인용 번호와 References 번호를 새로 일치시켜야 하며, 본문 등장 순서대로 일관되게 부여한다.
- 변환 후에는 원문 저자-연도 인용과 번호형 인용의 대응표를 유지해, 원문 대조와 추적이 가능하도록 한다.

## 파일 규칙

- 파일명은 원문 파일명에 `_논문_번역.md`를 붙여 작성한다.
- 새 파일을 만들 때는 먼저 원문 PDF 또는 텍스트를 확인하고, 번역본은 같은 폴더에 저장한다.
- 동일 이름의 `.txt`로 추출된 원문 파일을 우선적으로 참고하여 번역 작업을 진행한다.
- 원문 PDF가 없거나 텍스트를 확보할 수 없는 경우에는 새 번역 파일을 만들지 않고, 해당 파일을 건너뛰며 간단한 메모만 남긴다.
- 이미 번역본이 있는 파일은 중복 생성하지 않는다.

## 품질 기준

- 번역본은 “요약형”이 아니라 “전체 번역본”처럼 읽혀야 한다.
- 핵심 논점, 실험 방법, 결과, 해석이 누락되지 않았는지 확인한다.
- 원문과 비교해 정보의 순서가 바뀌지 않았는지 점검한다.
- 완료 전 원문과 번역본의 섹션 수, 표·그림 번호, 본문 인용, References 항목, 수치·단위·p값·신뢰구간을 대조한다.
- 원문에 있는 모든 Figure, Table, Chart의 번호와 캡션이 번역본에 있는지 대조하고, 원문 본문에서 참조한 그림·표 번호가 번역본 본문에도 유지되는지 확인한다.
- 자동 변환 완료 전 원문과 번역본의 페이지 수, 섹션 제목, 그림·표 번호, References 항목 수를 비교한다.
- 표 자동 변환 결과는 원문의 열 수, 행 수, 수치, 단위, ±, p값, 신뢰구간 및 각주가 보존됐는지 검증한다.
- 자동 변환이 표·그림·수식·각주·참고문헌의 구조를 확인하지 못하면 완료가 아니라 검토 필요 상태로 표시한다.
- 동일하거나 거의 동일한 문단, 그림·표 캡션 또는 섹션 제목이 반복되면 검토 필요 상태로 표시한다.
- 대조 과정에서 누락 또는 형식 불일치가 확인되면 번역본을 완료로 표시하지 않는다.
