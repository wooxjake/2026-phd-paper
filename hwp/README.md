# HWP 문서 관리 및 introduce.md 갱신 지침

## 1. 목적

이 폴더에는 학위논문 HWP/HWPX 원본, PDF 또는 TXT 추출본이 보관된다. 원본 문서의 최신 연구 내용을 작업용 Markdown 문서인 `../introduce.md`에 반영할 때 다음 지침을 적용한다.

이 폴더의 기본 동기화 방향은 다음과 같다.

```text
TXT 원본 -> ../introduce.md
```

`../introduce.md`를 기준으로 HWP 원본을 덮어쓰거나 수정하지 않는다.

## 2. 작업 전 README 확인 규칙

작업 대상 폴더에 `README.md`가 있으면 작업을 시작하기 전에 반드시 읽는다.

- 현재 접근한 폴더의 `README.md`를 가장 먼저 확인한다.
- 하위 폴더에서 작업할 때는 해당 하위 폴더의 `README.md`도 확인한다.
- 가까운 폴더의 README는 해당 폴더의 파일 관리와 변환 절차에 관한 세부 지침으로 적용한다.
- 루트의 `CLAUDE.md`, `.github/copilot-instructions.md` 및 관련 에이전트 지침은 프로젝트 전체 규칙으로 계속 적용한다.
- 폴더 README는 수정 승인 규칙을 대신하지 않는다. 파일을 변경하려면 현재 사용자 요청이 프로젝트의 수정 승인 조건을 충족해야 한다.
- README 사이에 충돌이 있으면 프로젝트 전체 규칙을 우선하고, 그다음 작업 대상에 가장 가까운 README를 적용한다.

따라서 `hwp/`의 HWP 문서를 읽거나 TXT 추출본을 이용하여 `introduce.md`를 갱신할 때에는 이 파일을 먼저 읽고 진행하는 것이 맞다.

## 3. 원본 파일 보호

다음 파일은 원본 자료로 취급하며, HWP 내용 갱신 작업 중에는 수정하지 않는다.

- `.hwp`, `.hwpx`, `.pdf` 원본
- 원본에서 추출한 `.txt` 파일
- 원본 문서의 이름 변경, 이동 및 삭제

사용자가 별도로 명시하지 않는 한 최신 원본을 확인하고 읽는 작업만 수행한다. 특히 최신 TXT 추출본을 이용하더라도 TXT 파일 자체를 정리하거나 재작성하지 않는다.

## 4. 최신 원본 판단

최신 파일은 파일명이나 파일 수정 시각만으로 단정하지 않는다.

1. 사용자가 특정 파일을 최신 원본으로 지정하면 그 파일을 우선한다.
2. 사용자의 지정이 없으면 파일명, 작성 단계, TXT 추출 여부와 문서 내부의 제목·본문을 함께 대조한다.
3. 사용자가 제공한 TXT 추출본을 사용한다.
4. 서로 다른 파일의 내용이 다르면 어느 파일을 기준으로 했는지 작업 결과에 기록한다.
5. 최신 여부가 확인되지 않으면 임의로 합치지 말고 `[확인 필요]`를 남긴다.

현재 사용자가 최신본으로 지정한 파일이 있으면 그 파일의 내용을 `introduce.md` 갱신 기준으로 삼는다.

## 5. introduce.md 갱신 절차

### 5.1 대조 범위

다음 항목을 장·절·문단 단위로 대조한다.

### 5.2 반영 방법

- 변경되지 않은 문단은 그대로 둔다.
- 원본의 최신 내용으로 기존 문단을 대체할 때는 기존 문단을 HTML 주석으로 보존한다.
- 주석 처리한 이전 문단 아래에 최신 원본 내용을 활성 문단으로 작성한다.
- 삭제된 것으로 보이는 내용은 원본에서 실제 삭제되었는지 확인하기 전까지 임의로 삭제하지 않는다.
- 원본에 새로 추가된 내용은 해당 장·절의 적절한 위치에 추가한다.
- 내용이 불명확하거나 TXT 추출 오류가 의심되면 원문을 복원하여 추측하지 말고 `[확인 필요]`로 표시한다.

권장 형식은 다음과 같다.

```markdown
<!-- 이전 introduce.md 내용
기존 문단
-->

최신 HWP 또는 TXT에서 확인한 문단
```

HTML 주석 안의 이전 문단은 최종 본문으로 해석되지 않도록 완전한 주석 블록으로 감싼다. 주석 안에 `-->`가 포함되는 경우에는 주석 구조가 깨지지 않도록 먼저 정리한다.

## 6. 동기화하지 않는 항목

다음 항목은 HWP에서 `introduce.md`로 자동 또는 무조건 복사하지 않는다.

- 표지, 제출 문구, 지도교수명 및 소속 표기
- 목차와 페이지 번호
- HWP의 글꼴, 여백, 줄 간격, 탭 및 페이지 나눔
- 그림 자체와 그림 파일의 배치
- 그림 목차와 표 목차
- TXT 추출 과정에서 생긴 `A`, `B`, `C`, `Figure .` 등의 위치 표시
- 문서 변환 과정에서 생긴 반복 문구, 깨진 띄어쓰기 및 무관한 문자열
- 참고문헌 전체 목록의 무조건적인 복사

그림 캡션은 그림 파일과 본문 내 위치가 확인된 뒤 별도로 반영한다. 그림이 없거나 캡션 번호가 불완전하면 캡션을 사실로 확정하지 말고 `[확인 필요]`를 표시한다.

## 7. 학술 내용과 인용 처리

- HWP 또는 TXT에 있는 문장이라도 원문 근거가 확인되지 않은 통계치, 표본 수, 장비 사양, 효과크기 및 결과를 새로 확정하지 않는다.
- 인용이 필요한 문장은 프로젝트 규칙에 따라 `[CITE?]`를 유지한다.
- 연구방법의 세부 수치와 계산식은 원본 문서에 명시된 경우에만 반영한다.
- 문헌을 새로 추가하거나 본문 인용 상태를 바꾸는 작업은 이 README의 단순 동기화 범위를 넘는다. 해당 작업을 별도로 요청받은 경우에만 프로젝트의 참고문헌 관리 규칙을 적용한다.
- HWP의 참고문헌 목록과 현재 프로젝트의 `references.md`가 다르면 임의로 합치지 말고 차이를 기록한다.

## 8. 형식 및 문체

- `introduce.md`의 기존 Markdown 구조와 한국어 학술 문체를 유지한다.
- HWP의 장·절 번호를 그대로 복사하기보다 `introduce.md`의 제목 단계와 기존 구조에 맞춘다.
- 연구 본문에 포함되는 문장은 한국어 학술 문체와 프로젝트의 인용 규칙을 따른다.
- 수식, 단위, 변수명 및 영문 약어는 원본과 현재 `introduce.md`의 정의가 일치하는지 확인한다.
- 원본의 그림 번호를 본문에서 언급할 때에는 실제 그림 파일 또는 확정된 캡션이 있는지 확인한다.

## 9. 작업 후 점검

갱신을 마친 뒤 다음을 확인한다.

- 변경된 파일이 `introduce.md`뿐인지 확인한다.
- HWP, HWPX, PDF 및 TXT 원본의 내용과 파일 상태가 변하지 않았는지 확인한다.
- 장·절 제목이 중복되거나 누락되지 않았는지 확인한다.
- 이전 내용이 HTML 주석 안에 보존되어 있는지 확인한다.
- 최신 내용이 주석 밖의 활성 Markdown으로 들어갔는지 확인한다.
- `Figure .`, 목차 페이지 번호, 추출 오류 문자열이 본문에 남아 있지 않은지 확인한다.
- `[확인 필요]`, `[CITE?]` 및 새로 확인해야 할 문헌을 별도로 기록한다.
- 원본 파일명, 사용한 TXT 추출본, 반영한 절과 미반영 항목을 작업 결과에 보고한다.

## 10. 작업 결과 보고 형식

작업을 마친 뒤 다음 항목을 간단히 보고한다.

```text
기준 원본: [파일명]
반영 대상: ../introduce.md
반영한 절: [장·절 목록]
주석 처리한 기존 내용: [문단 또는 절 목록]
반영하지 않은 항목: [그림, 목차, 확인 필요 항목 등]
원본 수정 여부: 수정하지 않음
```
